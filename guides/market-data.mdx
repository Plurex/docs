Venue operations are market data: what is trading on a venue. To place orders, read the matching host market instead (see [Venues](/concepts/venues)).

Each venue lists what it supports in its capabilities, and each market says which reads and streams it offers in `marketData`. Check them before calling; [Venue capabilities](/capabilities/venue-capabilities) explains both levels.

## Discover venues and markets

[List venues](/api-reference/platform/venues/list) returns every venue with its capabilities:

```bash
curl --request QUERY https://api.plurex.io/api/v1/venues/query/List \
  --header 'Content-Type: application/json' \
  --header "X-API-KEY: $PLUREX_API_KEY" \
  --header "X-API-SECRET: $PLUREX_API_SECRET" \
  --data '{}'
```

[List venue markets](/api-reference/platform/venues/list-markets) returns a venue's markets. Filter by exact `base` and `quote` assets, by instrument `types`, or with `search`, a fuzzy, case-insensitive match on the canonical symbol:

```json
{ "venueId": "bybit", "quote": "USDT", "types": ["Perp"], "search": "BTC" }
```

Both lists are [paged](/api-reference/platform/conventions#paging). Each market gives:

| Field | Use it for |
| --- | --- |
| `symbol` | The canonical symbol, such as `BTC-USDT-PERP`, for display and joining with host markets. |
| `instrument` | The value to send in every market-data request. |
| `increments` | The grid the venue quotes on: group book levels by `price` and format sizes by `size`. These are not order rules. |
| `contractDetails` | What one contract is. Book and trade sizes are in [native contracts](/concepts/instruments). |
| `marketData` | Which reads and streams this market supports, and on what terms. |

## Order books

The L2 book is every price level with the total size resting there, and every listed market has it. The L1 book is only the best bid and ask; check `marketData.orderBookL1` before you read it.

[Get the L2 order book](/api-reference/platform/venues/get-order-book-l2) returns the current book. Both sides list the best price first.

```bash
curl --request QUERY https://api.plurex.io/api/v1/venues/query/GetOrderBookL2 \
  --header 'Content-Type: application/json' \
  --header "X-API-KEY: $PLUREX_API_KEY" \
  --header "X-API-SECRET: $PLUREX_API_SECRET" \
  --data '{"venueId": "bybit", "instrument": {"type": "Perp", "base": "BTC", "quote": "USDT"}}'
```

```json
{
  "data": {
    "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" },
    "bids": [
      { "price": "64012.4", "size": "1.204" },
      { "price": "64012.3", "size": "0.350" }
    ],
    "asks": [
      { "price": "64012.5", "size": "0.812" },
      { "price": "64012.7", "size": "2.000" }
    ],
    "asOf": "2026-10-25T09:30:00.250Z"
  }
}
```

[Get the L1 order book](/api-reference/platform/venues/get-order-book-l1) takes the same request and returns the best bid and ask, each with its `price` and the total `size` there. A side is `null` when the venue reports nothing on it.

`asOf` is the time the book is current as of. It can be the time of your read, even when the last change arrived earlier. An unknown or unsupported market returns `422 NotSupported`.

## Recent trades

[Get recent trades](/api-reference/platform/venues/get-recent-trades) returns the venue's recent public trades, oldest first. The venue decides how many; it is not a complete history.

```json
{
  "data": {
    "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" },
    "trades": [
      { "price": "64012.4", "size": "0.010", "takerSide": "Sell", "observedAt": "2026-10-25T09:29:59.870Z", "receivedAt": "2026-10-25T09:29:59.902Z" },
      { "price": "64012.5", "size": "0.125", "takerSide": "Buy", "observedAt": "2026-10-25T09:30:00.105Z", "receivedAt": "2026-10-25T09:30:00.131Z" }
    ],
    "asOf": "2026-10-25T09:30:00.250Z"
  }
}
```

`takerSide` is the aggressor's side, or `null` when the venue does not report it. Trades carry no ID, so do not try to deduplicate them by identity across reads.

## Prices, statistics, funding and open interest

Four observation reads each take one `venueId` and one `instrument`, and return that market's current value with its timestamps:

| Operation | Returns | Market entry to check |
| --- | --- | --- |
| [Get a price](/api-reference/platform/venues/get-price) | The price of one `kind`: `Traded`, `Mark` or `Index` | `marketData.prices.traded`, `.mark` or `.index` |
| [Get market statistics](/api-reference/platform/venues/get-market-statistics) | Open, high, low, previous close and volumes over the market's window | `marketData.statistics` |
| [Get indicative funding](/api-reference/platform/venues/get-indicative-funding) | Indicative funding rate and next funding time, for perpetuals | `marketData.indicativeFunding` |
| [Get open interest](/api-reference/platform/venues/get-open-interest) | Open interest, for derivatives | `marketData.openInterest` |

```bash
curl --request QUERY https://api.plurex.io/api/v1/venues/query/GetPrice \
  --header 'Content-Type: application/json' \
  --header "X-API-KEY: $PLUREX_API_KEY" \
  --header "X-API-SECRET: $PLUREX_API_SECRET" \
  --data '{
    "venueId": "bybit",
    "kind": "Mark",
    "instrument": {"type": "Perp", "base": "BTC", "quote": "USDT"}
  }'
```

```json
{
  "data": {
    "value": { "price": "64013.1" },
    "observedAt": "2026-10-25T09:30:00.120Z",
    "confirmedAt": "2026-10-25T09:30:01Z",
    "receivedAt": "2026-10-25T09:30:00.135Z"
  }
}
```

A market the venue does not list, or one whose entry is `null` or whose `get` is `false`, returns `422 NotSupported`. Price kinds are never relabelled: a market without a mark price returns `422 NotSupported` for `Mark`, not its traded price. To read many markets, send one request per market, choosing them from their `marketData` first (see [Venue capabilities](/capabilities/venue-capabilities#unsupported-markets)).

### Judge freshness

Judge freshness by `confirmedAt`, falling back to `observedAt`: an unchanged price on a quiet market keeps an early `observedAt` while `confirmedAt` moves forward. A value the venue stops reporting becomes `null`. See [Timestamps and freshness](/concepts/venues#timestamps-and-freshness).

### Read the terms of each value

- **Statistics windows differ by venue.** Read `marketData.statistics.window`: `Rolling` with an ISO 8601 `length` such as `PT24H`, or `CalendarDay` in a named `timeZone`. Two venues' 24-hour figures need not cover the same period. Fields outside `supportedFields` are always `null`.
- **Indicative funding is an estimate.** The rate that settles can differ from the one you read; read settled rates from the [funding history](#funding-history).
- **Open interest has a unit.** `unit` is `Contracts`, `BaseAsset` or `QuoteAsset`, and is also listed in `marketData.openInterest.unit`. Convert before comparing venues.

## Candles

[List candles](/api-reference/platform/venues/list-candles) returns closed candles for one market, price kind and interval, newest first across every page. The candle still forming is never included, and a page has no gaps: there is one candle for every interval it spans.

Before you call, read the market's `marketData.candles` entry for the price kind (`traded`, `mark` or `index`):

- The interval must be in `supportedIntervals`. Intervals are aligned to whole multiples from the Unix epoch, in UTC.
- `list` allows `ByInstrument`, which starts from the latest closed candle.
- `listBefore` allows `ByInstrumentBefore`, which starts from candles that end at or before `before`, and is needed to page past the first page with either variant.

```json
{
  "venueId": "bybit",
  "priceKind": "Traded",
  "interval": "Hour1",
  "query": {
    "type": "ByInstrument",
    "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" }
  }
}
```

```json
{
  "items": [
    {
      "startAt": "2026-10-25T08:00:00Z",
      "endAt": "2026-10-25T09:00:00Z",
      "open": "63880.1",
      "high": "64120.0",
      "low": "63790.5",
      "close": "64010.2",
      "volume": { "asset": "BTC", "value": "1532.118" },
      "turnover": { "asset": "USDT", "value": "97934821.55" }
    }
  ],
  "nextCursor": "eyJiIjoiMjAyNi0xMC0yNVQwODowMDowMFoifQ"
}
```

Each candle covers `[startAt, endAt)`. `volume` and `turnover` name their asset, because the asset depends on the market, and are `null` when the venue does not report them.

To start at a point in the past, use `ByInstrumentBefore`:

```json
{
  "venueId": "bybit",
  "priceKind": "Traded",
  "interval": "Hour1",
  "query": {
    "type": "ByInstrumentBefore",
    "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" },
    "before": "2026-10-20T00:00:00Z"
  }
}
```

### Page back in time

Send each `nextCursor` with the same venue, price kind, interval and query until it is `null` or you reach the start time you need:

```python
from datetime import datetime
import os
import requests

URL = "https://api.plurex.io/api/v1/venues/query/ListCandles"
HEADERS = {"X-API-KEY": os.environ["PLUREX_API_KEY"], "X-API-SECRET": os.environ["PLUREX_API_SECRET"]}

def parse(timestamp):
    return datetime.fromisoformat(timestamp.replace("Z", "+00:00"))

def candles_back_to(start_at, query, venue_id="bybit", price_kind="Traded", interval="Hour1"):
    """Yield closed candles newest first, stopping before start_at (an aware datetime)."""
    body = {"venueId": venue_id, "priceKind": price_kind, "interval": interval, "query": query}
    while True:
        response = requests.request("QUERY", URL, json=body, headers=HEADERS, timeout=10)
        response.raise_for_status()
        page = response.json()
        for candle in page["items"]:
            if parse(candle["startAt"]) < start_at:
                return
            yield candle
        if page["nextCursor"] is None:
            return
        body["cursor"] = page["nextCursor"]
```

History does not reach back forever: before the start of the history available, a page is empty.

## Funding history

[List funding periods](/api-reference/platform/venues/list-funding-periods) returns the finalised funding rates of one perpetual, newest first across every page. Check that the market's `marketData.fundingPeriods` is non-null and its `list` is `true`; any other market returns `422 NotSupported`.

```bash
curl --request QUERY https://api.plurex.io/api/v1/venues/query/ListFundingPeriods \
  --header 'Content-Type: application/json' \
  --header "X-API-KEY: $PLUREX_API_KEY" \
  --header "X-API-SECRET: $PLUREX_API_SECRET" \
  --data '{
    "venueId": "bybit",
    "query": {"type": "ByInstrument", "instrument": {"type": "Perp", "base": "BTC", "quote": "USDT"}}
  }'
```

```json
{
  "items": [
    { "fundingTime": "2026-10-25T08:00:00Z", "rate": "0.0001" },
    { "fundingTime": "2026-10-25T00:00:00Z", "rate": "-0.000025" }
  ],
  "nextCursor": "eyJjb250aW51YXRpb24iOiJjdXJzb3ItMiJ9"
}
```

Each `FundingPeriod` is one funding that has settled: `fundingTime` is when it applied, and `rate` is the fraction of position value paid. A positive rate means longs pay shorts; a negative rate means shorts pay longs. These are the venue's rates; your account's own funding payments are in its [transactions](/guides/portfolio#transactions).

Page back in time as you do for candles. A funding period carries no interval: read the funding times rather than assuming a schedule.

## Follow market data live

Stream when you follow a market continuously: a book you trade against, a live tape, a chart's forming candle. Use the reads for a one-off value. Each stream follows one market, so open one stream per market you follow.

Every market data stream starts with a **Reset** holding the current state, then sends **Updates**. A Reset can arrive again at any time; it replaces everything you hold for that stream. [Streams](/guides/streams) covers opening, keepalives, ending and reopening.

| Stream | Reset | Update | Check support |
| --- | --- | --- | --- |
| [Stream the L2 order book](/api-reference/platform/venues/subscribe-to-order-book-l2s) | The whole book, best price first | The levels that changed | Always supported |
| [Stream the L1 order book](/api-reference/platform/venues/subscribe-to-order-book-l1s) | The best bid and ask | The complete new top of book | `marketData.orderBookL1.subscribe` |
| [Stream public trades](/api-reference/platform/venues/subscribe-to-trades) | The recent trades | New trades | Always supported |
| [Stream a price](/api-reference/platform/venues/subscribe-to-prices) | The current price of one `kind` | The complete new value | `marketData.prices.<kind>.subscribe` |
| [Stream market statistics](/api-reference/platform/venues/subscribe-to-market-statistics) | The current statistics | The complete new values | `marketData.statistics.subscribe` |
| [Stream indicative funding](/api-reference/platform/venues/subscribe-to-indicative-fundings) | The current estimate | The complete new value | `marketData.indicativeFunding.subscribe` |
| [Stream open interest](/api-reference/platform/venues/subscribe-to-open-interests) | The current amount | The complete new value | `marketData.openInterest.subscribe` |
| [Stream candles](/api-reference/platform/venues/subscribe-to-candles) | The recent candles, ending with the forming one | The forming candle | `marketData.candles.<priceKind>.subscribe` |

The last column applies when the venue's capability is `PerMarket`; `NotSupported` means no market streams it. Funding history has no stream. A market the venue does not list, or one whose entry says `false`, returns `422 NotSupported` before the stream starts.

### Keep a book

An L2 order book Update lists only the levels that changed, each with its new total size. Set each level to that size and remove a level whose size is `0`; levels not listed are unchanged. On a Reset, drop your book and start again from its levels.

```json
{"type":"Reset","timestamp":"2026-10-27T09:00:00.120Z","data":{"bids":[{"price":"67250.1","size":"0.42"}],"asks":[{"price":"67250.2","size":"0.08"}],"observedAt":"2026-10-27T09:00:00.101Z","receivedAt":"2026-10-27T09:00:00.115Z"}}
{"type":"Update","timestamp":"2026-10-27T09:00:00.320Z","data":{"bids":[{"price":"67250.1","size":"0.9"}],"asks":[{"price":"67250.2","size":"0"}],"observedAt":"2026-10-27T09:00:00.301Z","receivedAt":"2026-10-27T09:00:00.316Z"}}
```

After these two lines the book has a bid of 0.9 at 67250.1 and no ask at 67250.2.

When the stream stops, with or without an Ended line, the book you hold is no longer current: open the stream again. [A resilient reader](/guides/streams#a-resilient-reader) keeps a book across reopens.

### Top of book, trades, values and candles

- **L1 order book.** Every Reset and Update carries the complete top of book: replace the `bid` and `ask` you hold. A side that is now `null` was cleared.
- **Trades.** A trades Reset is the recent trades, as Get recent trades returns them, and it can repeat trades an Update already delivered. Replace the history you hold with it; do not add it to running totals such as traded volume. Updates carry only new trades, oldest first.
- **Prices, statistics, funding and open interest.** Each Update carries the complete value, so a field that is now `null` was cleared. A stream value carries `observedAt` and `receivedAt`, with the same meanings as in a read, but no `confirmedAt`.
- **Candles.** The Reset is the recent candles, oldest first, ending with the candle still forming. Each Update is the forming candle: one with the same `startAt` replaces it, and one with a later `startAt` completes it and starts the next. Updates never move back in time. Read older candles with List candles. A series that streams does so at every interval in its `supportedIntervals`.

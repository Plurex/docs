title: "Balances, positions and settings"
description: "Read an account's balances, positions and margin, set leverage and position mode safely, and reconcile balance postings."
---

These operations tell you what an account holds and how its markets are configured. They work the same way for real and paper accounts, and every one needs your API key and the `accountId`.

| To read or change | Use |
| --- | --- |
| Asset balances | [List wallets](/api-reference/platform/hosts/list-wallets) |
| Open derivative positions | [List open positions](/api-reference/platform/hosts/list-positions) |
| Margin per margin group | [List margin states](/api-reference/platform/hosts/list-margin-states) |
| Everything about one market | [Get market account state](/api-reference/platform/hosts/get-market-state) |
| Leverage | [Get market leverage](/api-reference/platform/hosts/get-leverage), [Set market leverage](/api-reference/platform/hosts/set-leverage) |
| Position mode | [Get market position mode](/api-reference/platform/hosts/get-position-mode), [Set market position mode](/api-reference/platform/hosts/set-position-mode) |
| Fees, funding, deposits and other postings | [List account transactions](/api-reference/platform/hosts/list-transactions) |

<Note>
  Every list on this page is paged. Omit `cursor` for the first page and send each `nextCursor` back with the same query until it is `null`, even if you usually get everything in one page.
</Note>

## Balances

[List wallets](/api-reference/platform/hosts/list-wallets) returns one entry per asset, and per wallet where the host keeps several:

```json
{ "accountId": "acc_123" }
```

```json
{
  "items": [
    { "id": null, "name": null, "asset": "USDT", "totalBalance": "10250.40", "availableBalance": "8710.15" },
    { "id": null, "name": null, "asset": "BTC", "totalBalance": "0.150", "availableBalance": "0.150" }
  ],
  "nextCursor": null
}
```

`totalBalance` is everything the wallet holds; `availableBalance` is what is free to use. `id` and `name` are `null` when the host has a single unnamed wallet per asset.

## Positions

[List open positions](/api-reference/platform/hosts/list-positions) returns one entry per derivative market with an open position. Every entry has both a `long` and a `short` leg, so the same shape covers hedged and netted positions:

```json
{
  "items": [
    {
      "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" },
      "long": {
        "size": "0.250", "entryPrice": "61250.5", "markPrice": "61500.0",
        "unrealizedPnl": { "asset": "USDT", "value": "62.375" }
      },
      "short": { "size": "0", "entryPrice": null, "markPrice": null, "unrealizedPnl": null },
      "mode": "Netting"
    }
  ],
  "nextCursor": null
}
```

- Sizes are in native contracts, not base units. Convert with the market's `contractDetails`; see [Instruments](/concepts/instruments).
- A leg with no exposure has size `"0"`. In `Hedging` mode both legs can be open at once.
- Each leg's `markPrice` is the price it is valued at, and `unrealizedPnl` is its profit or loss if it closed at that
  price, in the settlement asset. Use `size` to tell whether a leg is open, rather than relying on these being `null`.
- `entryPrice`, `markPrice`, `unrealizedPnl` and `mode` are `null` when the host does not report them. A host can
  report `unrealizedPnl` without `markPrice`, so read each field on its own.

## Margin

[List margin states](/api-reference/platform/hosts/list-margin-states) returns the account's margin per margin group: the collateral asset, total collateral value, initial and maintenance margin, and `accountMarginRatio` when the host reports it.

```json
{
  "items": [
    {
      "baseCollateralAsset": "USDT",
      "totalCollateralValue": "10250.40",
      "totalInitialMargin": "1531.26",
      "totalMaintenanceMargin": "76.56",
      "accountMarginRatio": "0.0075"
    }
  ],
  "nextCursor": null
}
```

## One market at a glance

[Get market account state](/api-reference/platform/hosts/get-market-state) gathers what matters for one market into a single read. The result's `type` depends on the market:

```json
{
  "accountId": "acc_123",
  "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" }
}
```

    ```json
            "unrealizedPnl": { "asset": "USDT", "value": "62.375" }
    ```

    The available base and quote balances:


## Leverage

Leverage is a setting on a market, never a field on an order. Whether you can read or change it depends on two levels:

1. The host's `capabilities.marketSettings.getMarketLeverage` and `setMarketLeverage` must not be `NotSupported`.
2. The market's `settings.leverage` (from [List host markets](/api-reference/platform/hosts/list-markets)) must be non-null. Inside it, `get` says whether you can read it, and `setEffectScope` is `null` when it cannot be set.

```json
{ "min": "1", "max": "100", "step": "0.01", "get": true, "setEffectScope": { "type": "Market" } }
```

### Read it

[Get market leverage](/api-reference/platform/hosts/get-leverage) returns one of three settings:

| `type` | Meaning |
| --- | --- |
| `Leveraged` | Leverage is on, at `leverage`. |
| `Disabled` | The market has a leverage control and it is off for this account, so orders are not leveraged. |
| `Unknown` | The host cannot report the setting truthfully. `message` says why. |

`Disabled` is different from a `null` `settings.leverage`, which means the market has no leverage control at all.

### Set it

[Set market leverage](/api-reference/platform/hosts/set-leverage) takes a value on the market's grid: between `min` and `max` inclusive, and exactly `min` plus a whole number of `step`s. With the example above, `12.34` is valid, `12.345` is not. When `min` equals `max`, that single value is the only one accepted. Plurex does not round an off-grid value; it rejects it with `422 Rejected`.

```json
{
  "accountId": "acc_123",
  "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" },
  "leverage": "10"
}
```

The response is the resulting setting. Setting the same value again is safe.

<Warning>
  Check `setEffectScope` before you set. `Market` changes only this market; `MarketGroup` changes a host-defined group of markets; `Account` changes every market on the account. After a wider change, read the setting again on every market you trade instead of assuming the old values still hold.
</Warning>

## Position mode

Position mode decides whether a market holds long and short exposure separately (`Hedging`) or as one net position (`Netting`). The market's `settings.positionMode` lists the modes it accepts in `values`, whether you can read the mode (`get`), and how far a change reaches (`setEffectScope`, `null` when it cannot be set). The host's `marketSettings.getMarketPositionMode` and `setMarketPositionMode` capabilities must also allow it.

```json
{
  "accountId": "acc_123",
  "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" },
  "mode": "Hedging"
}
```

[Set market position mode](/api-reference/platform/hosts/set-position-mode) returns the resulting mode and is safe to repeat with the same value.

Position mode and an order's `positionEffect` are independent. Whether you may send `positionEffect` (`Open` or `Close`) is decided only by the order type's `supportsPositionEffect` flag on the market, never by the position mode. Read each flag on its own.

## Transactions

[List account transactions](/api-reference/platform/hosts/list-transactions) returns the account's balance postings: trading fees, funding payments, interest, deposits, withdrawals and so on. Check the host's `accountTransactions.listTransactions` capability first; a host without transaction history returns `422 NotSupported`.

```json
{ "accountId": "acc_123" }
```

```json
{
  "items": [
    {
      "id": "txn_40213",
      "effectiveAt": "2026-10-25T08:00:00Z",
      "amount": { "asset": "USDT", "value": "-1.27" },
      "type": "FundingPayment",
      "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" },
      "orderId": null,
      "fillId": null,
      "positionId": null,
      "groupId": null,
      "nativeType": "SETTLEMENT",
      "description": null
    }
  ],
  "nextCursor": "eyJwIjoyfQ"
}
```

How to read a posting:

- **`amount` is signed** from your side: positive increases the balance, negative decreases it. A fee you pay is negative; a deposit is positive.
- **`type`** classifies the posting: `TradingFee`, `FundingPayment`, `BorrowInterest`, `Financing`, `LiquidationFee`, `Settlement`, `Rebate`, `Deposit`, `Withdrawal`, `Transfer`, `Conversion`, `Adjustment` or `Other`. `nativeType` keeps the host's own label. The host's `supportedTransactionTypes` lists the types it reports. Treat a type you do not recognise as `Other`.
- **Links** to an `instrument`, order, fill or position are present only when the host reports them reliably; otherwise they are `null`.
- **`groupId`** links postings that come from one host record, such as the legs of a conversion and its fee, when the host reports it.
- **`id`** is stable: it never changes and is the same ID the [transaction stream](/guides/streams#transaction-events) sends.
- **`effectiveAt`** is when the posting took effect.

Results come in the order the `listTransactions` capability's `defaultOrdering` states, `Chronological` or `ReverseChronological`, across all pages.

### Reconcile postings

Because IDs are stable, deduplicate by `id`. To stay complete:

- Combine history with the [transaction stream](/guides/streams) where `subscribeToAccountTransactions` is supported: connect, read history, then add streamed postings you do not have.
- After a disconnect, or on each polling pass, re-read recent history back past the newest posting you already hold, and add any IDs you have not seen. Overlap with what you already hold instead of stopping at the first known ID, so a posting that appears late is still picked up.
- Do not rebuild a ledger from wallet balances, fills or orders. Postings are the record of what changed a balance.

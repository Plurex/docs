The Platform API is a JSON-over-HTTP API, with streams as long-lived HTTP responses. This reference is generated from the Plurex OpenAPI specification. For concepts and how-to guides, start with [How Plurex works](/how-plurex-works).

## Base URL

Every operation and stream is under `https://api.plurex.io`.

## Specification

The specification is the contract. Use it to generate clients or validate payloads.

| Document | Covers |
| --- | --- |
| OpenAPI 3.2 (`plurex-platform-api.yaml`) | Every operation and stream, schema and error |

Every operation and stream page in this reference is rendered from it.

<Note>
  The specification uses OpenAPI 3.2 union nullability (`type: [string, 'null']`). If you generate a client, check that your generator decodes explicit `null` values. Also treat `ErrorCode` and other enums as open: new values can appear without a new API version. Stream responses use OpenAPI 3.2 `itemSchema` to describe each line; generators that predate it may not type them.
</Note>

## Commands, queries and streams

Every operation is one of three kinds, and its path says which:

| Kind | What it does | Request | Safe to repeat |
| --- | --- | --- | --- |
| Query | Reads state | `POST /api/v1/{domain}/query/{Action}` | Always |
| Command | Changes state | `POST /api/v1/{domain}/command/{Action}` | Stated per command |
| Stream | Follows one topic and sends its changes | `POST /api/v1/{domain}/stream/{Action}` | Yes: opening it again starts a new stream |

Every kind takes a JSON body, and IDs go in the body, never in the path. There are no `GET`, `PUT` or `DELETE` resources. [Commands, queries and streams](/how-plurex-works#commands-queries-and-streams) explains why.

A stream's `200` response stays open and carries one JSON message per line (`application/jsonl`). Each stream page shows the message union under its `200` response; errors before the stream starts are ordinary responses. Streams are listed beside their query operations. See [Streams](/guides/streams).

## Authentication

Every operation and stream needs both headers:

```http
X-API-KEY: <your API key>
X-API-SECRET: <your API secret>
```

Create keys and find your tenant ID on the **DevTools** page of the [Plurex app](https://platform.plurex.io). See [Authentication](/authentication).

## Badges

Each operation page shows its badges below the request line, starting with its kind: Query, Command or Stream. Hover a badge for its meaning.

| Badge | Meaning |
| --- | --- |
| Query | Reads state and changes nothing. Always safe to repeat. |
| Command | Changes state. Safe to repeat unless it has the Not safe to repeat badge. |
| Stream | The response stays open and carries one JSON message per line until an `Ended` line. See [Streams](/guides/streams). |
| Check capabilities | Not every host or venue supports this operation. Check its [capabilities](/capabilities/overview) first, or expect `422 NotSupported`. |
| Paged | Returns pages. Follow `nextCursor` until it is `null`. |
| Batch | Takes a list of identifiers or instruments and handles them in one call. Each operation says what it returns for each item. |
| Not safe to repeat | Repeating the call repeats its effect. If the outcome is unclear, check before retrying. Commands without this badge are safe to repeat. |

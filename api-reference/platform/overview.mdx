The Platform API is command and query RPC over HTTP, with long-lived streams. You call an operation by name with a JSON body rather than acting on resources: commands change state, queries read it, and streams stay open to send you changes as they happen.

For concepts and how-to guides, start with [How Plurex works](/how-plurex-works).

## Commands, queries and streams

Every operation is one of three kinds, and its path says which:

| Kind | What it does | Request | Safe to repeat |
| --- | --- | --- | --- |
| Query | Reads state | `QUERY /api/v1/{domain}/query/{Action}` | Always |
| Command | Changes state | `POST /api/v1/{domain}/command/{Action}` | Unless it has the Not safe to repeat badge |
| Stream | Follows one topic and sends its changes | `QUERY /api/v1/{domain}/stream/{Action}` | Yes: opening it again starts a new stream |

There are no `GET`, `PUT` or `DELETE` resources. [Requests](/api-reference/platform/conventions#requests) has the rules, and [How Plurex works](/how-plurex-works#commands-queries-and-streams) explains why.

Each stream page shows its message union under the `200` response, and streams are listed beside their query operations. See [Streams](/guides/streams).

## Base URL

Every operation and stream is under `https://api.plurex.io`.

## Specification

The OpenAPI 3.2 specification (`plurex-platform-api.yaml`) is the contract. It covers every operation, stream, schema and error, and this reference is generated from it. Use it to generate clients or validate payloads.

<Note>
  Queries and streams use the OpenAPI 3.2 `query` method, and stream responses use `itemSchema` to describe each line; generators that predate 3.2 may not handle them. If yours drops `query` operations, call them with [`POST`](/api-reference/platform/conventions#when-you-cannot-send-query) instead. Check that yours decodes explicit `null` values (`type: [string, 'null']`), and treat `ErrorCode` and other enums as [open](/api-reference/platform/conventions#compatibility): new values can appear without a new API version.
</Note>

## Domains

| Domain | Operations |
| --- | --- |
| [`venues`](/api-reference/platform/venues/list) | Market data: venues, markets, L1 and L2 order books, trades, prices, statistics, indicative funding, funding history, open interest and candles, as queries and streams |
| [`hosts`](/api-reference/platform/hosts/list) | Hosts and their markets, then trading on an account: orders, fills, balances, positions, margin, settings and transactions |
| [`accounts`](/api-reference/platform/accounts/connect) | Connect, list and manage your accounts |
| [`paper`](/api-reference/platform/paper/create) | Create, fund and draw down paper accounts, and read and choose their fee tiers |

## Authentication

Every operation and stream needs both the `X-API-KEY` and `X-API-SECRET` headers. See [Authentication](/authentication).

## Badges

Each operation page shows its badges below the request line: first its kind, then any of these. Hover a badge for its meaning.

| Badge | Meaning |
| --- | --- |
| Check capabilities | Not every host or venue supports this operation. Check its [capabilities](/capabilities/overview) first, or expect `422 NotSupported`. |
| Paged | Returns pages. Follow `nextCursor` until it is `null`. |
| Batch | Takes a list of identifiers and handles them in one call. Each operation says what it returns for each item. |
| Not safe to repeat | Repeating the call repeats its effect; if the outcome is unclear, check before retrying. |

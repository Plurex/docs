A host holds trading accounts and executes orders on a venue's markets: an exchange's own account service, or a [paper host](/paper/overview) that simulates one. Every account action goes through a host, and every host uses the same operations and the same shapes. For step-by-step trading, see [Orders](/guides/orders), [Streams](/guides/streams) and [Portfolio](/guides/portfolio).

## Promise only what every host can keep

**A field is required only when every supported host can report it truthfully.** Anything a host may not report is nullable, and `null` always means "the host did not report it". Plurex never estimates, derives or backfills a value the host did not give.

| Field | When it is `null` | What Plurex does not do |
| --- | --- | --- |
| `Order.averagePrice` | The host does not report an average execution price, even when `sizeTraded` is above zero. | Calculate it from fills. |
| `Order.sizing` (market orders) | The host does not report both the amount and its unit. | Infer the unit from fills or default to one. |
| `Order.clientOrderId` | None was submitted, or the host does not report it. | Fill it in from your request. |
| `Fill.id` | The host has no execution ID. | Invent one. |
| `Fill.role` | The host does not say whether you were maker or taker. | Guess from price or timing. |
| `Position.entryPrice` | The host does not report it. | Compute it from your fills. |
| `Position.markPrice`, `unrealizedPnl` | The host does not report them; `unrealizedPnl` also when the leg is empty. | Value the position at a price it chose. |
| `AccountTransaction.orderId`, `fillId`, `positionId` | The host does not report the link reliably. | Match postings to orders by time or amount. |

Where hosts differ in what they *support*, the difference is declared in their [capabilities](/capabilities/overview) and market summaries.

## The host header

[List hosts](/api-reference/platform/hosts/list) returns one `HostHeader` per host, real and paper:

| Field | Meaning |
| --- | --- |
| `id` | The host ID you pass as `hostId`, for example `bybit` or `bybit-paper`. |
| `venueIds` | The venues this host executes on. Read it as a list. |
| `isPaper` | `true` for a paper host. |
| `modelHostId` | For a paper host, the real host whose markets and order rules it simulates. `null` for a real host. |
| `supportedCredentialTypes` | How accounts are created: `ApiKey` for hosts you connect with exchange credentials, `Paper` for paper hosts. |
| `capabilities` | Every operation the host offers, grouped by area, with each variant's support. See [Host capabilities](/capabilities/host-capabilities). |

## Host markets

[List host markets](/api-reference/platform/hosts/list-markets) returns the markets you can trade on a host. Each `HostMarketSummary` has:

- `venueId`, `symbol` and `instrument`, which join it to the [venue market](/concepts/venues-and-hosts#joining-a-venue-market-to-a-host-market);
- `contractDetails`, which says what one contract is (see [Instruments and sizing](/concepts/instruments));
- `orderTypes`: `limit` is always present; `market`, `triggerLimit` and `triggerMarket` are `null` where the market does not offer them. Each carries the market's **order rules**: increments, minimums and the options it accepts;
- `settings`: `leverage` and `positionMode`, each `null` where the market has no such setting.

Plurex validates orders against exactly these rules and never rounds your input. See [Order rules](/capabilities/order-rules).

## Orders

Submit one of four order types with [Submit an order](/api-reference/platform/hosts/submit-order):

| Type | Priced by | Sized by |
| --- | --- | --- |
| `Limit` | `price` | `size` in native contracts |
| `Market` | best available | `sizing`: `Size` (native contracts) or `Notional` (quote asset) |
| `TriggerLimit` | `price`, placed when the `trigger` fires | `size` |
| `TriggerMarket` | best available, when the `trigger` fires | `sizing` |

The host returns an `Order`, the same shape that [Get an order](/api-reference/platform/hosts/get-order), the list operations and the order stream return. It is host-reported state.

An order's `state` is `Live`, `Filled`, `Cancelled` or `Rejected`. There is no `PartiallyFilled` state: check `sizeTraded`. There is no `updatedAt`: an order has `createdAt`, and each fill has its own `executedAt`. See [Order states](/guides/orders#order-states).

### What an order does not echo

The options you submit (`tif`, `postOnly`, `reduceOnly`, `positionEffect`) are not echoed back. Keep your own record of what you sent, keyed by `id` or `clientOrderId`.

For `Market` and `TriggerMarket` orders, `sizing` is the requested amount and unit as the host accepted it. The host may round a notional.

## Fills

[List fills](/api-reference/platform/hosts/list-fills) returns executions for one order, one instrument or the whole account; which variants a host offers is in its capabilities. A fill's `side` is **your** side, which is your order's side, not the aggressor's side. Its `size` is in native contracts.

## Portfolio

Four reads describe what the account holds. See [Balances, positions and settings](/guides/portfolio).

| Operation | Returns |
| --- | --- |
| [List wallets](/api-reference/platform/hosts/list-wallets) | One `Wallet` per balance. |
| [List open positions](/api-reference/platform/hosts/list-positions) | One `MarketPosition` per open position. An instrument can appear more than once. |
| [List margin states](/api-reference/platform/hosts/list-margin-states) | One `AccountMarginState` per margin group. |
| [Get market account state](/api-reference/platform/hosts/get-market-state) | Balances, position, collateral and leverage for one market, as a `Derivative`, `Spot` or `SpotMargin` result. |

A `MarketPosition` always has both a `long` and a `short` leg. `size` is in native contracts and never negative: the leg gives the direction, and an empty leg has size `"0"`. In `Netting` mode long and short net into one side, so at most one leg is non-empty. In `Hedging` mode both can be open at once.

## Market settings: leverage and position mode

Leverage and position mode are **settings of a market on your account**, not fields on an order. A market's `settings` says whether each exists there, and `setEffectScope` says what a change affects: it can reach beyond one market. See [Order rules](/capabilities/order-rules#settings) for what each market declares, and [Leverage](/guides/portfolio#leverage) and [Position mode](/guides/portfolio#position-mode) for reading and changing them.

## Transactions

[List account transactions](/api-reference/platform/hosts/list-transactions) returns the account's balance postings: the ledger behind its wallets. Each `AccountTransaction` is one posting of one asset. `amount` is signed from your point of view: positive increases the balance, negative decreases it. `id` is stable within the account and identical in history and in the [transaction stream](/api-reference/platform/hosts/subscribe-to-account-transactions), so you can merge the two without duplicates.

See [Transactions](/guides/portfolio#transactions) for posting types, ordering and reconciling.

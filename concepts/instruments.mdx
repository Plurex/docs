Plurex identifies an instrument by what it is, not by what a venue calls it: its type, base asset, quote asset and, where they apply, expiry, strike and right. The same instrument has the same identity on every venue and host.

## The instrument

An `Instrument` is a JSON object with a `type` discriminator. Every operation that takes a market takes a structured instrument; there is no symbol-only input.

| `type` | Contract | Fields |
| --- | --- | --- |
| `Spot` | Spot pair | `base`, `quote` |
| `Perp` | Perpetual | `base`, `quote` |
| `PerpInv` | Inverse perpetual | `base`, `quote` |
| `Future` | Dated future | `base`, `quote`, `expiry` |
| `FutureInv` | Inverse dated future | `base`, `quote`, `expiry` |
| `Option` | Option | `base`, `quote`, `expiry`, `strike`, `right` |

```json
{ "type": "Perp", "base": "ETH", "quote": "USDT" }
```

```json
{ "type": "Future", "base": "BTC", "quote": "USD", "expiry": "2030-03-29" }
```

```json
{ "type": "Option", "base": "BTC", "quote": "USD", "expiry": "2030-03-29", "strike": "50000", "right": "Call" }
```

### Field rules

- **Asset IDs** (`base`, `quote`) are uppercase and contain only `A`–`Z`, `0`–`9` and dots, 1 to 32 characters, with no `-` or `_`. Digits are allowed anywhere, as in `1000PEPE`. Different assets are different instruments: `BTC`/`USDT` and `BTC`/`USDC` are separate markets.
- **`expiry`** is a date, `YYYY-MM-DD`.
- **`strike`** is a positive decimal string in the quote asset, in canonical form: no exponent and no trailing fractional zeros. Send `"50000"` or `"50000.5"`, never `"50000.0"` or `"5E4"`; non-canonical strikes are rejected with `422 ValidationFailed`.
- **`right`** is `Call` or `Put`.
- An unknown `type` is rejected with `400 InvalidRequest`. In responses, new instrument types may appear over time: treat an unknown `type` as unrecognised rather than failing.

### What is listed

Discover what is actually tradable with [List host markets](/api-reference/platform/hosts/list-markets) and [List venue markets](/api-reference/platform/venues/list-markets). The current venues list spot and perpetual markets.

**Options are modelled but not listed or tradable.** Neither listing returns option markets. An `Option` instrument appears only where a host reports account activity on one, for example in a position or transaction, so your code can read that data instead of failing on it.

## Canonical symbols

Every market summary carries a `symbol`: the canonical symbol for its instrument, in the form `BASE-QUOTE-TYPE`:

| `type` | Type token | Example instrument | Canonical symbol |
| --- | --- | --- | --- |
| `Spot` | `SPOT` | BTC/USDT spot | `BTC-USDT-SPOT` |
| `Perp` | `PERP` | ETH/USDT linear perpetual | `ETH-USDT-PERP` |
| `PerpInv` | `PERPINV` | BTC/USD inverse perpetual | `BTC-USD-PERPINV` |
| `Future` | `FUT_YYYYMMDD` | BTC/USD future expiring 2030-03-29 | `BTC-USD-FUT_20300329` |
| `FutureInv` | `FUTINV_YYYYMMDD` | BTC/USD inverse future expiring 2030-03-29 | `BTC-USD-FUTINV_20300329` |
| `Option` | `OPT_YYYYMMDD_STRIKE_RIGHT` | BTC/USD 50000 call expiring 2030-03-29 | `BTC-USD-OPT_20300329_50000_CALL` |

`YYYYMMDD` is the `expiry` without dashes, `STRIKE` is the `strike` exactly as given, and `RIGHT` is `CALL` or `PUT`. A put at a fractional strike reads `BTC-USD-OPT_20300329_50000.5_PUT`.

Use the symbol for display, logging and as a map key: it is the same on a host market and the venue market it trades on. It is **not an input**: send the structured `instrument` to every operation. It is also not the venue's own identifier, so do not pass it to an exchange directly. To search markets by symbol, use the `search` filter on either listing.

## Contract details

Each host and venue market has `contractDetails`, which says what one contract of the market is: `contractSize` units of `contractSizeAsset`. It also gives the `contractType` (`Spot`, `Linear`, `Inverse` or `Quanto`) and the `settlementAsset`, which is `null` for spot markets. See [Order rules](/capabilities/order-rules#contract-details-what-a-size-means).

## Size is always native contracts

**Every `size` is in native contracts**: order sizes, fill sizes, position sizes, order book and trade sizes, and the size rules on host markets. A size is not necessarily an amount of the base asset. **Every `notional` is an amount of the quote asset.**

Read `contractDetails` and convert.

### Linear perpetual: one contract is one BTC

```json
{
  "contractType": "Linear",
  "settlementAsset": "USDT",
  "contractSize": "1",
  "contractSizeAsset": "BTC"
}
```

On this BTC/USDT perpetual, `"size": "0.015"` is 0.015 contracts of 1 BTC each: a position of 0.015 BTC. At a price of 64,000 USDT it is worth 960 USDT.

### Inverse perpetual: one contract is one USD

```json
{
  "contractType": "Inverse",
  "settlementAsset": "BTC",
  "contractSize": "1",
  "contractSizeAsset": "USD"
}
```

On this BTC/USD inverse perpetual, `"size": "250"` is 250 contracts of 1 USD each: **250 USD of exposure, not 250 BTC.** At a price of 64,000 USD that is about 0.0039 BTC, and the BTC amount changes as the price moves while the USD amount does not. This ordinary-looking order means something very different from the linear case:

```json
{
  "type": "Limit",
  "instrument": { "type": "PerpInv", "base": "BTC", "quote": "USD" },
  "side": "Buy",
  "size": "250",
  "price": "64000.0",
  "reduceOnly": false,
  "tif": "GTC"
}
```

### Contracts that are not one unit

When `contractSize` is not 1, multiply. If a market's contract were `0.001` BTC, then `"size": "15"` would be 15 contracts, or 0.015 BTC. Always read `contractSize` from the live market summary rather than assuming 1.

## Value and market order sizing

Host markets set a minimum **value** for limit and trigger limit orders, computed from price, size and `contractDetails`. A size above the market's minimum size can still be below its minimum value, so check both.

Market and trigger market orders take `sizing` instead of `size`: `Size` is native contracts, and `Notional` is an amount of the quote asset. A notional is not a size promise: the size you receive is the notional divided by the fill price, and can fall below the market's minimum size.

[Order rules](/capabilities/order-rules) has the value calculation, the units each market accepts and how to round.

## Decimals

Prices, sizes, notionals, balances and rates are exact decimals encoded as JSON strings, such as `"0.015"`. Parse them with a decimal type, not a binary float, and send them back as strings. See [API conventions](/api-reference/platform/conventions#decimals-and-timestamps).

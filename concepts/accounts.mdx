Every trading action in Plurex happens on an **account**, and every account belongs to a **tenant**.

## Tenants

The tenant is the owner of trading resources. There are two kinds: you, as a user, and an [organisation](/platform/organisations), which a team shares. Every account belongs to exactly one tenant, and API keys are created under it.

- **Find the tenant ID** on the [DevTools](/platform/api-keys) page of the Plurex app. Yours is there while you work as yourself, and each organisation's while it is selected.
- **API keys reach only what you grant.** Each key belongs to the tenant and has its own access: which accounts it can reach, and whether it can read, trade, manage paper funds or administer them. See [API keys and access](/platform/api-keys).
- **Tenant-wide operations take a `tenantId`:** [Connect](/api-reference/platform/accounts/connect), [List accounts](/api-reference/platform/accounts/list) and [Create a paper account](/api-reference/platform/paper/create).

See [Authentication](/authentication) for creating keys and sending them.

## Accounts

An account is your account on one host. It lives on exactly one host for its whole life, and every operation on it takes only its `accountId`. You never pass a `hostId` or `tenantId` to trade.

```json
{
  "id": "acc_7f3c2a91",
  "tenantId": "ten_4b8e10d2",
  "hostId": "bybit",
  "isPaper": false,
  "name": "Main Bybit",
  "credential": { "publicValue": "Xk29fLq8TzQ1vB7c", "credentialType": "ApiKey" }
}
```

`credential.publicValue` is the non-secret part of the credential, such as the API key, so you can tell which key an account uses. The secret is never returned. For a paper account `publicValue` is `null` and `credentialType` is `Paper`.

### Real and paper accounts

| | Real account | Paper account |
| --- | --- | --- |
| Host | A real host, such as `bybit` or `valr` | A paper host, such as `bybit-paper` or `valr-paper` |
| Created with | [Connect](/api-reference/platform/accounts/connect), using the exchange's API credentials | [Create a paper account](/api-reference/platform/paper/create) |
| `isPaper` | `false` | `true` |
| Money | Real funds on the exchange | Simulated balances you add with [Deposit](/api-reference/platform/paper/deposit) |

Creation is the only part that differs. After that, both kinds are traded and managed through the same operations, so code written against a paper account runs against a real one by switching the `accountId`. Read each host's capabilities before you switch, because paper and real hosts publish their own. See [Going live](/paper/going-live).

## Connecting an exchange account

[Connect](/api-reference/platform/accounts/connect) adds an exchange account using its API credentials. The host must list `ApiKey` in `supportedCredentialTypes`.

```bash
curl --request POST https://api.plurex.io/api/v1/accounts/command/Connect \
  --header 'Content-Type: application/json' \
  --header "X-API-KEY: $PLUREX_API_KEY" \
  --header "X-API-SECRET: $PLUREX_API_SECRET" \
  --data '{
    "tenantId": "'"$PLUREX_TENANT_ID"'",
    "name": "Main Bybit",
    "hostId": "bybit",
    "credential": {
      "type": "ApiKey",
      "publicKey": "YOUR_EXCHANGE_API_KEY",
      "secretKey": "YOUR_EXCHANGE_API_SECRET"
    }
  }'
```

Plurex checks the key with the exchange before connecting:

- **The key must allow reading and trading.**
- **Bybit keys must belong to a Unified Trading Account.**
- **A refused key creates no account.** `422 InvalidProviderCredentials` means the exchange rejected the key: it is invalid, expired or revoked. `422 ProviderAccessDenied` means the key works but lacks the access the account needs, such as trading. Retrying with the same key will not help: fix its permissions at the exchange, or create a new key, then connect again. [Update credentials](/api-reference/platform/accounts/update-connection) checks a new key the same way.

To connect through the web app instead, see [Connect an exchange account](/platform/add-exchange).

## Creating a paper account

[Create a paper account](/api-reference/platform/paper/create) takes your `tenantId`, a `name` and the `hostId` of a **paper** host. Find paper hosts with [List hosts](/api-reference/platform/hosts/list): they have `isPaper: true`, and `modelHostId` names the real host each one simulates.

```json
{
  "tenantId": "ten_4b8e10d2",
  "name": "BTC perp forward test",
  "hostId": "bybit-paper"
}
```

A new paper account starts with no balances; fund it with [Deposit](/api-reference/platform/paper/deposit). See [Paper trading](/paper/overview).

## Account lifecycle

| Operation | What it does |
| --- | --- |
| [Connect](/api-reference/platform/accounts/connect) | Connects an exchange account. |
| [Create a paper account](/api-reference/platform/paper/create) | Creates a paper account on a paper host, optionally on a `feeTier` from [Get paper host fee tiers](/api-reference/platform/paper/get-host-fee-tiers). |
| [Update credentials](/api-reference/platform/accounts/update-connection) | Replaces a connected account's exchange credentials, for example when you rotate keys. The new key is checked like a new connection, but Plurex does not check that it belongs to the same exchange account, so use a key for that account. |
| [Rename](/api-reference/platform/accounts/rename) | Changes the account's name. |
| [Delete](/api-reference/platform/accounts/delete) | Removes the account from Plurex. A paper account's open orders are cancelled and its positions closed at market; a real account's orders and positions stay on the exchange. |
| [List accounts](/api-reference/platform/accounts/list) | Lists the tenant's accounts, optionally only on some hosts (`hostIds`), only paper or real (`isPaper`), or by name (`search`, where every word must match). |
| [Get an account](/api-reference/platform/accounts/get) | Returns one account. |

For example, to list only your paper accounts:

```json
{
  "tenantId": "ten_4b8e10d2",
  "isPaper": true
}
```

## Retry safety

A timeout or `5xx` does not prove that a command had no effect. Connect and Create a paper account are not safe to repeat: a repeat adds another account. Before you retry, check [List accounts](/api-reference/platform/accounts/list) and identify the account by what it is:

- After an unclear Connect, look for an account on the `hostId` you sent whose `credential.publicValue` is the exchange key you sent.
- After an unclear Create, compare the list for that paper `hostId` with the accounts you already knew about.

Names are labels only: two accounts can share one, so don't rely on them to tell accounts apart.

After an unclear Delete, check List accounts: if the account is gone, the delete succeeded. Repeating a Delete that succeeded returns `404 AccountNotFound`. See [Errors](/api-reference/platform/errors#retries-by-operation) for every other operation and error code.

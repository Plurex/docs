A venue is an exchange where markets trade and prices form. Every venue operation is market data, and like every operation it needs an API key. This page explains the model behind that data, so you know exactly what each value means and how fresh it is. For step-by-step recipes, see [Market data](/guides/market-data).

## Venues and their capabilities

[List venues](/api-reference/platform/venues/list) returns each venue's `id` and its `capabilities`: every market-data operation the venue offers, with its support.

- `GetOrderBookL2` and `GetRecentTrades`, and their streams, are always supported, on every venue and every market it lists.
- Every other read and stream belongs to the market, so its support is `PerMarket` or `NotSupported`. `PerMarket` means the venue offers it and each market's `marketData` entry says whether that market does.
- `NotSupported` means no market on the venue has it, and calls return `422 NotSupported`. For example, a venue that publishes no index prices declares `prices.index.getPrice` as `NotSupported`.

See [Venue capabilities](/capabilities/venue-capabilities) for the full structure and how to resolve support for one market.

## Venue markets

[List venue markets](/api-reference/platform/venues/list-markets) returns a venue's markets, filtered by `base`, `quote`, `types` or a fuzzy `search` on the canonical symbol. The listing is paged; follow `nextCursor` until it is `null`.

Each `VenueMarketSummary` describes one market:

| Field | Meaning |
| --- | --- |
| `symbol` | The canonical symbol, such as `BTC-USDT-PERP`. For display and lookup; never sent as input. |
| `instrument` | The structured instrument you send to every market-data operation. |
| `increments` | The grid the venue quotes market data on: `price` for book levels and trade prices, `size` for book level sizes in native contracts. **Not order rules.** |
| `contractDetails` | What one contract is. Every size in market data is in native contracts. See [Instruments and sizing](/concepts/instruments). |
| `marketData` | Which reads and streams this market supports, and on what terms. |

A BTC/USDT linear perpetual on a venue that reports all three price kinds might look like this (values are illustrative; read the live summary):

```json
{
  "symbol": "BTC-USDT-PERP",
  "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" },
  "increments": { "price": "0.1", "size": "0.001" },
  "contractDetails": {
    "contractType": "Linear",
    "settlementAsset": "USDT",
    "contractSize": "1",
    "contractSizeAsset": "BTC"
  },
  "marketData": {
    "prices": {
      "traded": { "get": true, "subscribe": true },
      "mark": { "get": true, "subscribe": true },
      "index": { "get": true, "subscribe": true }
    },
    "orderBookL1": { "get": true, "subscribe": true },
    "statistics": {
      "window": { "type": "Rolling", "length": "PT24H" },
      "supportedFields": ["Open", "High", "Low", "VolumeBase", "VolumeQuote"],
      "get": true,
      "subscribe": true
    },
    "indicativeFunding": { "get": true, "subscribe": true },
    "openInterest": { "unit": "Contracts", "get": true, "subscribe": true },
    "candles": {
      "traded": {
        "supportedIntervals": ["Minute1", "Minute5", "Minute15", "Hour1", "Hour4", "Day1"],
        "list": true,
        "listBefore": true,
        "subscribe": true
      },
      "mark": null,
      "index": null
    },
    "fundingPeriods": { "list": true }
  }
}
```

A `null` entry in `marketData` means the market does not offer that data. A non-null entry still has its own `get`, `subscribe`, `list` or `listBefore` flags; check them.

Use `increments.price` to set display precision (its decimal scale) and to group book levels in whole multiples of it. An increment, not a number of decimals, is used because a tick such as `0.5` cannot be expressed as a precision. Never price or size an order from `increments`: order rules come from the [host market](/concepts/hosts#host-markets).

Option markets are not listed.

## Order books and recent trades

A market's order book comes at two levels:

| Level | What it is | Read | Stream | Support |
| --- | --- | --- | --- | --- |
| L2 | Every price level with the total size resting there | [Get the L2 order book](/api-reference/platform/venues/get-order-book-l2) | [Stream the L2 order book](/api-reference/platform/venues/subscribe-to-order-book-l2s) | Always supported |
| L1 | The top of book: the best bid and ask, each with the total size there | [Get the L1 order book](/api-reference/platform/venues/get-order-book-l1) | [Stream the L1 order book](/api-reference/platform/venues/subscribe-to-order-book-l1s) | `marketData.orderBookL1` |

[Get the L2 order book](/api-reference/platform/venues/get-order-book-l2) returns the current book of one market:

```json
{
  "data": {
    "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" },
    "bids": [
      { "price": "64012.4", "size": "1.250" },
      { "price": "64012.3", "size": "0.400" }
    ],
    "asks": [
      { "price": "64012.5", "size": "0.873" },
      { "price": "64012.7", "size": "2.010" }
    ],
    "asOf": "2026-10-25T09:30:00.120Z"
  }
}
```

- `bids` are best (highest) first; `asks` are best (lowest) first.
- Level sizes are native contracts.
- `asOf` is the time the book is current as of. It can be the time of your read, even when the last change arrived earlier.

[Get the L1 order book](/api-reference/platform/venues/get-order-book-l1) returns only the top of book, in its own shape: `bid` and `ask` are single levels, each with a `price` and a `size` in native contracts. A side is `null` when the venue reports nothing on it. Use L1 when you need only the best prices; use L2 when you need depth.

```json
{
  "data": {
    "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" },
    "bid": { "price": "64012.4", "size": "1.250" },
    "ask": { "price": "64012.5", "size": "0.873" },
    "asOf": "2026-10-25T09:30:00.120Z"
  }
}
```

[Get recent trades](/api-reference/platform/venues/get-recent-trades) returns the venue's recent public trades, oldest first, with an `asOf`. The venue bounds how many come back; it is not a complete history. Each `PublicTrade` has a `price`, a `size` in native contracts, the `takerSide` (`null` when the venue does not report the aggressor), the venue time `observedAt` and the time Plurex received it, `receivedAt`. Public trades carry no identity. Trade sizes can be finer than `increments.size`, for example a fill of an order sized by notional.

For every order book and trades read, an unknown or unsupported market returns `422 NotSupported`; an unknown venue returns `404 NotFound`.

## Observations

There is no "ticker" operation. A ticker bundles last price, best bid and ask, 24-hour statistics and funding into one object, as if they were observed together. They rarely are: each value updates on its own schedule, and venues define them differently. Plurex returns each observation separately, with its own venue time, so you never act on a value that is older than it looks. Ask for the specific observations your strategy uses, and read the best bid and ask from the [L1 order book](#order-books-and-recent-trades).

| Read | Value | Market entry | Notes |
| --- | --- | --- | --- |
| [Get a price](/api-reference/platform/venues/get-price) | `price` | `marketData.prices.{traded,mark,index}` | One `kind` per request: `Traded`, `Mark` or `Index`. |
| [Get market statistics](/api-reference/platform/venues/get-market-statistics) | `window`, `open`, `high`, `low`, `previousClose`, `volumeBase`, `volumeQuote` | `marketData.statistics` | Fields outside `supportedFields` are always `null`. |
| [Get indicative funding](/api-reference/platform/venues/get-indicative-funding) | `rate`, `nextFundingTime` | `marketData.indicativeFunding` | Perpetuals only. |
| [Get open interest](/api-reference/platform/venues/get-open-interest) | `amount`, `unit` | `marketData.openInterest` | Derivatives only. |

Each read takes one `venueId` and one `instrument`, and returns that market's observation: the `value` with its timestamps.

```json
{
  "venueId": "bybit",
  "kind": "Mark",
  "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" }
}
```

```json
{
  "data": {
    "value": { "price": "64012.5" },
    "observedAt": "2026-10-25T09:30:00.120Z",
    "confirmedAt": "2026-10-25T09:30:01.000Z",
    "receivedAt": "2026-10-25T09:30:00.135Z"
  }
}
```

A market the venue does not list, or one that does not support the read, returns `422 NotSupported`; check `marketData` before asking. To read several markets, send one request per market; to follow them continuously, open a [stream](#streams) for each.

### Prices by kind

`PriceKind` says what the venue reports a price to be. **Kinds are never relabelled or derived from one another.** If a market has no index price, Plurex does not substitute the mark price, and it does not compute a mark price from the order book. Request a kind the market does not report and you get `422 NotSupported`.

| Kind | What it is |
| --- | --- |
| `Traded` | The venue's last traded price. |
| `Mark` | The venue's mark price for a derivative. |
| `Index` | The venue's index price for a derivative's underlying. |

Mark, index, funding and open interest are what the venue reports. They are not the terms a particular host applies to your position.

### Statistics windows

Statistics are computed by the venue over the market's declared `window`: `Rolling` with an ISO 8601 `length` such as `PT24H`, or `CalendarDay` in an IANA `timeZone`. Two venues' windows need not mean the same, so read `window` before comparing "24-hour" figures across venues. `volumeBase` is in the base asset and `volumeQuote` in the quote asset.

### Indicative funding

The indicative funding `rate` is the venue's current estimate of a perpetual's funding rate, with the `nextFundingTime` when the venue gives it. The rate that actually settles can differ: read settled rates from the [funding history](#funding-history). Your own funding payments appear in the account's [transactions](/concepts/hosts#transactions).

### Open interest

`unit` says how `amount` is measured: `Contracts`, `BaseAsset` or `QuoteAsset`. It is fixed per market and declared in `marketData.openInterest.unit`. Convert with `contractDetails` before comparing open interest across venues.

## Timestamps and freshness

Every observation carries up to three times:

| Field | Meaning |
| --- | --- |
| `observedAt` | Venue time of the value. `null` when the venue gives none. |
| `confirmedAt` | The latest venue time at which the value was confirmed current, even if it did not change. `null` when it has not been confirmed. |
| `receivedAt` | When Plurex received the value. |

**Judge freshness by `confirmedAt`, falling back to `observedAt`.** A price that has not moved for a minute can still be current: `confirmedAt` tells you it was still the venue's value at that time. `receivedAt` is not venue time, so it says nothing about how old the value was when the venue produced it.

```python
from datetime import datetime, timedelta, timezone

def is_fresh(observation, max_age: timedelta) -> bool:
    venue_time = observation["confirmedAt"] or observation["observedAt"]
    if venue_time is None:
        return False  # no venue time: decide your own policy
    as_of = datetime.fromisoformat(venue_time.replace("Z", "+00:00"))
    return datetime.now(timezone.utc) - as_of <= max_age
```

Stale data looks stale. When a venue stops reporting a value, Plurex clears it rather than serving the last one it saw: `price` and open interest `amount` become `null`. A `null` value inside an observation means "no current value", never zero.

## Candles

[List candles](/api-reference/platform/venues/list-candles) returns OHLC candles for one market, one price kind and one interval.

- **Closed only.** The candle still forming is never included.
- **Newest first**, within and across pages.
- **No gaps within a page:** one candle for every interval the page spans.
- **Aligned to UTC.** Each `CandleInterval` (`Minute1`, `Minute3`, `Minute5`, `Minute15`, `Minute30`, `Hour1`, `Hour2`, `Hour4`, `Hour6`, `Hour12`, `Day1`) is aligned to whole multiples of itself from the Unix epoch, in UTC.
- **Half-open.** A candle covers `[startAt, endAt)`.

```json
{
  "venueId": "bybit",
  "priceKind": "Traded",
  "interval": "Hour1",
  "query": {
    "type": "ByInstrumentBefore",
    "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" },
    "before": "2026-10-25T00:00:00Z"
  }
}
```

```json
{
  "items": [
    {
      "startAt": "2026-10-24T23:00:00Z",
      "endAt": "2026-10-25T00:00:00Z",
      "open": "63880.1",
      "high": "64105.0",
      "low": "63850.2",
      "close": "64012.5",
      "volume": { "asset": "BTC", "value": "1520.441" },
      "turnover": { "asset": "USDT", "value": "97240311.52" }
    }
  ],
  "nextCursor": "CURSOR_FROM_PREVIOUS_RESPONSE"
}
```

There are two variants. `ByInstrument` starts from the latest closed candle. `ByInstrumentBefore` starts from the candles that end at or before `before`. Follow `nextCursor` back in time until it is `null`. History does not reach back forever: before the start of the history available, a page is empty.

Each market declares its candle series per price kind in `marketData.candles`:

| Field | Meaning |
| --- | --- |
| `supportedIntervals` | The intervals you may request. |
| `list` | `ByInstrument` is available. |
| `listBefore` | `ByInstrumentBefore` is available, and so is paging past the first page. |
| `subscribe` | The candle stream is available, at every supported interval. |

Read these from the live summary rather than hard-coding them. A price kind, interval or variant the market does not list returns `422 NotSupported`.

`volume` and `turnover` are `AssetValue`s, each naming its asset, because a bare number is ambiguous: on an inverse market the volume may be counted in the quote asset. Either is `null` when the venue does not report it.

## Funding history

[List funding periods](/api-reference/platform/venues/list-funding-periods) returns the finalised funding rates of one perpetual, newest first within and across pages. Each `FundingPeriod` has a `fundingTime`, when the funding applied, and the `rate` that settled then: the fraction of position value paid per funding. A positive rate means longs pay shorts; a negative rate means shorts pay longs.

```json
{
  "venueId": "bybit",
  "query": {
    "type": "ByInstrument",
    "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" }
  }
}
```

```json
{
  "items": [
    { "fundingTime": "2026-10-25T08:00:00Z", "rate": "0.0001" },
    { "fundingTime": "2026-10-25T00:00:00Z", "rate": "-0.000025" }
  ],
  "nextCursor": "CURSOR_FROM_PREVIOUS_RESPONSE"
}
```

`ByInstrument` starts from the most recent finalised period. Follow `nextCursor`, with the same query, until it is `null`. The market's `marketData.fundingPeriods` is non-null only for a perpetual with funding history, and its `list` flag says whether you can list it; any other market returns `422 NotSupported`.

The rates are the venue's. Your own funding payments, which depend on your host and position, appear in the account's [transactions](/concepts/hosts#transactions).

## Streams

Each read has a stream that follows one market: its L2 or L1 order book, trades, a price kind, statistics, indicative funding, open interest or a candle series. Funding history has no stream. A stream starts with a **Reset** holding the current state, then sends **Updates**; a Reset can come again at any time and replaces everything you hold. Each market says whether it streams a value with the `subscribe` flag in its `marketData` entry.

Stream values carry `observedAt` and `receivedAt`, with the meanings above, but no `confirmedAt`. See [Read market data](/guides/market-data#follow-market-data-live) for applying Updates and [Streams](/guides/streams) for opening and reopening a stream.

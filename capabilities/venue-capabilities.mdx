title: "Venue capabilities"
description: "Which market-data reads and streams each venue and market supports, on what terms, and how to resolve one before you call it."
---

A venue's capabilities say which market-data reads and streams it offers: L2 and L1 order books, recent trades, prices of each kind, statistics, indicative funding, open interest, candles and funding history. Each of its markets then says which of those reads and streams it supports, and on what terms: which candle intervals, over what statistics window, in what open-interest unit.

Read venue headers with [List venues](/api-reference/platform/venues/list) and market summaries with [List venue markets](/api-reference/platform/venues/list-markets). Both are paged.

```bash
curl --request POST https://api.plurex.io/api/v1/venues/query/ListMarkets \
  --header 'Content-Type: application/json' \
  --header "X-API-KEY: $PLUREX_API_KEY" \
  --header "X-API-SECRET: $PLUREX_API_SECRET" \
  --data '{ "venueId": "bybit", "types": ["Perp"] }'
```

Venue IDs in examples on this page are illustrative. Discover venues with List.

## The header

`VenueHeader` has an `id` and `capabilities`, a `VenueCapabilities` tree. Every entry is always present.

```text
capabilities
├─ orderBookL2        getOrderBookL2 · subscribeToOrderBookL2s          always Supported
├─ trades             getRecentTrades · subscribeToTrades               always Supported
├─ prices             <kind>.getPrice · <kind>.subscribeToPrices        for traded, mark, index
├─ orderBookL1        getOrderBookL1 · subscribeToOrderBookL1s
├─ statistics         getMarketStatistics · subscribeToMarketStatistics
├─ indicativeFunding  getIndicativeFunding · subscribeToIndicativeFundings
├─ openInterest       getOpenInterest · subscribeToOpenInterests
├─ candles            listCandles.byInstrument · listCandles.byInstrumentBefore   (paged)
│                     subscribeToCandles
└─ fundingPeriods     listFundingPeriods.byInstrument                   (paged)
```

The L2 order book and trades are always supported: their leaves are `Supported` on every venue, for every market it lists. Every other entry belongs to the market, so it is a `MarketSupport`, either `PerMarket` or `NotSupported`, never `Supported`:

- `PerMarket`: the venue offers it, and each market's `marketData` says whether that market does.
- `NotSupported`: no market on the venue has it, for example a venue that reports no index prices. Calls return `422 NotSupported`.

## Market data on each market

`VenueMarketSummary.marketData` is a `VenueMarketData`. Each entry is a descriptor: `null` when the market does not have that data, otherwise an object with a flag for each read or stream and the terms you need.

| Entry | `null` when | Flags | Terms |
| --- | --- | --- | --- |
| [`prices.traded`](/api-reference/platform/venues/get-price), [`.mark`](/api-reference/platform/venues/get-price), [`.index`](/api-reference/platform/venues/get-price) | The market does not report that price kind | `get`, `subscribe` | |
| [`orderBookL1`](/api-reference/platform/venues/get-order-book-l1) | The market has no best quote | `get`, `subscribe` | |
| [`statistics`](/api-reference/platform/venues/get-market-statistics) | The market has no statistics | `get`, `subscribe` | `window`, `supportedFields` |
| [`indicativeFunding`](/api-reference/platform/venues/get-indicative-funding) | The market is not a perpetual with indicative funding | `get`, `subscribe` | |
| [`openInterest`](/api-reference/platform/venues/get-open-interest) | The market is not a derivative with open interest | `get`, `subscribe` | `unit` |
| [`candles.traded`](/api-reference/platform/venues/list-candles), [`.mark`](/api-reference/platform/venues/list-candles), [`.index`](/api-reference/platform/venues/list-candles) | The market has no candles of that price kind | `list`, `listBefore`, `subscribe` | `supportedIntervals` |
| [`fundingPeriods`](/api-reference/platform/venues/list-funding-periods) | The market is not a perpetual with funding history | `list` | |

`prices` and `candles` are always objects; their per-kind entries are the nullable descriptors. The L2 order book and trades have no entry: every listed market has them.

### Prices

Each price kind is separate. `Traded`, `Mark` and `Index` are what the venue reports each price to be: kinds are never relabelled or derived from one another, so a market without a mark price has `prices.mark: null` rather than a traded price in its place.

### L1 order book

`orderBookL1` says whether you can read and stream the market's top of book. Every L1 level carries both a `price` and a `size`. If you need depth beyond the best level, read the L2 order book, which every listed market supports.

### Statistics

`window` says what the statistics cover. Two venues' windows need not mean the same, so read it rather than assume 24 hours:

- `{"type": "Rolling", "length": "PT24H"}`: a window of that ISO 8601 length ending now.
- `{"type": "CalendarDay", "timeZone": "..."}`: the current calendar day in that IANA time zone.

`supportedFields` lists the `StatisticsField` values the venue reports: `Open`, `High`, `Low`, `PreviousClose`, `VolumeBase`, `VolumeQuote`. Fields not listed are always `null` in results.

### Indicative funding and open interest

Indicative funding is offered only on perpetuals, and open interest only on derivatives. `openInterest.unit` says what the amount counts: `Contracts`, `BaseAsset` or `QuoteAsset`. Units differ between venues; convert `Contracts` with the market's `contractDetails` before comparing.

### Candles

Each price kind has its own `CandleSeriesSpec`:

| Field | Meaning |
| --- | --- |
| `supportedIntervals` | The `CandleInterval` values you can request, from `Minute1` to `Day1`. Every listed interval is available to each supported variant. |
| `list` | `ListCandles` with `ByInstrument`: the latest closed candles. |
| `listBefore` | `ListCandles` with `ByInstrumentBefore`, and continuing past the first page of either variant. |
| `subscribe` | `SubscribeToCandles` for this series, at every interval in `supportedIntervals`. |

At least one of `list` and `listBefore` is `true`. Candles are aligned to whole multiples of the interval from the Unix epoch, in UTC. ListCandles returns closed candles only, newest first, with no gaps.

### Funding history

`fundingPeriods` is present only on a perpetual with funding history. Its `list` flag says whether [ListFundingPeriods](/api-reference/platform/venues/list-funding-periods) with `ByInstrument` works on the market, including every page after the first. Indicative funding and funding history are separate entries: a market can have one without the other, so check each.

## Resolve a read or stream

Check the header leaf, then the market descriptor and its terms. The header alone is enough only for the L2 order book and trades.

| Read | Header leaf | Market check |
| --- | --- | --- |
| GetOrderBookL2, GetRecentTrades | Always supported | The venue lists the market |
| GetPrice, kind `K` | [`prices.<k>.getPrice`](/api-reference/platform/venues/get-price) | [`marketData.prices.<k>`](/api-reference/platform/venues/get-price) non-null and `get` is `true` |
| GetOrderBookL1 | [`orderBookL1.getOrderBookL1`](/api-reference/platform/venues/get-order-book-l1) | [`marketData.orderBookL1`](/api-reference/platform/venues/get-order-book-l1) non-null and `get` is `true` |
| GetMarketStatistics | [`statistics.getMarketStatistics`](/api-reference/platform/venues/get-market-statistics) | [`marketData.statistics`](/api-reference/platform/venues/get-market-statistics) non-null and `get` is `true` |
| GetIndicativeFunding | [`indicativeFunding.getIndicativeFunding`](/api-reference/platform/venues/get-indicative-funding) | [`marketData.indicativeFunding`](/api-reference/platform/venues/get-indicative-funding) non-null and `get` is `true` |
| GetOpenInterest | [`openInterest.getOpenInterest`](/api-reference/platform/venues/get-open-interest) | [`marketData.openInterest`](/api-reference/platform/venues/get-open-interest) non-null and `get` is `true` |
| ListCandles `ByInstrument` | [`candles.listCandles.byInstrument`](/api-reference/platform/venues/list-candles) | [`marketData.candles.<k>`](/api-reference/platform/venues/list-candles) non-null, `list` is `true`, interval in `supportedIntervals` |
| ListCandles `ByInstrumentBefore`, or any page after the first | [`candles.listCandles.byInstrumentBefore`](/api-reference/platform/venues/list-candles) | The same, with `listBefore` `true` |
| ListFundingPeriods `ByInstrument` | [`fundingPeriods.listFundingPeriods.byInstrument`](/api-reference/platform/venues/list-funding-periods) | [`marketData.fundingPeriods`](/api-reference/platform/venues/list-funding-periods) non-null and `list` is `true` |
| SubscribeToOrderBookL2s, SubscribeToTrades | Always supported | The venue lists the market |
| Any other stream | The read's area, with `subscribeTo…` in place of `get…` (for example [`prices.<k>.subscribeToPrices`](/api-reference/platform/venues/subscribe-to-prices)) | The same descriptor non-null and `subscribe` is `true`; for candles, also the interval in `supportedIntervals` |

Here `<k>` is the lowerCamel price kind (`traded`, `mark`, `index`) for the request's `Traded`, `Mark` or `Index`.

```python
KIND = {"Traded": "traded", "Mark": "mark", "Index": "index"}

def can_list_candles(venue, market, price_kind, interval, before=False):
    leaf = venue["capabilities"]["candles"]["listCandles"]["byInstrumentBefore" if before else "byInstrument"]
    if leaf["type"] != "PerMarket":
        return False
    series = market["marketData"]["candles"][KIND[price_kind]]
    if series is None or interval not in series["supportedIntervals"]:
        return False
    return series["listBefore"] if before else series["list"]

def can_list_funding_periods(venue, market):
    leaf = venue["capabilities"]["fundingPeriods"]["listFundingPeriods"]["byInstrument"]
    spec = market["marketData"]["fundingPeriods"]
    return leaf["type"] == "PerMarket" and spec is not None and spec["list"]
```

## Unsupported markets

Every venue read and stream takes one market. A market the venue does not list, or one that does not support the read or stream, returns `422 NotSupported`, and a stream returns it before it starts. An unknown venue returns `404 NotFound`.

`422 NotSupported` is avoidable: filter markets by their capabilities before you call. To read the mark price of every perpetual that has one, pick the markets first, then send one [GetPrice](/api-reference/platform/venues/get-price) request per market:

```python
def mark_price_markets(venue, markets):
    if venue["capabilities"]["prices"]["mark"]["getPrice"]["type"] != "PerMarket":
        return []
    return [m["instrument"] for m in markets
            if (spec := m["marketData"]["prices"]["mark"]) is not None and spec["get"]]
```

```json
{
  "venueId": "bybit",
  "kind": "Mark",
  "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" }
}
```

Still handle `422 NotSupported`: a market's support can change between your last refresh and the read. Refresh the market summaries when you get one.

## Page through candle history

To load history for a series, request the latest page with `ByInstrument`, then follow `nextCursor` back in time until it is `null`. Following the cursor needs `listBefore`. To start from a point in the past, use `ByInstrumentBefore`, which returns candles that end at or before `before`:

```json
{
  "venueId": "bybit",
  "priceKind": "Mark",
  "interval": "Hour1",
  "query": {
    "type": "ByInstrumentBefore",
    "instrument": { "type": "Perp", "base": "BTC", "quote": "USDT" },
    "before": "2026-10-20T00:00:00Z"
  }
}
```

History does not reach back forever: before the start of the history available, a page is empty. A request for an interval the series does not list, or for a price kind the market has no candles of, returns `422 NotSupported`.

## Increments are not order rules

`increments` is the grid the venue quotes market data on. Book levels and trade prices sit on `increments.price`, and book level sizes on `increments.size`; use them for display precision and for grouping book levels in whole multiples. Trade sizes can be finer, for example a fill of an order sized by notional.

They are not order rules. Never price or size an order from a venue market; use the host's [market order rules](/capabilities/order-rules). See [Read market data](/guides/market-data) for reading and streaming the data itself.

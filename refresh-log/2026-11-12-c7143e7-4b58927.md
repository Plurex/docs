## Topics

### Orders gain a Pending state

`Pending` is an order the host accepted and has not reported working: open, cancellable, nothing traded reported. It
comes only before `Live`, and an order need not pass through it. The order stream opens an order when first seen past
`Pending`, so a `Pending` order in the `Reset` opens later and a `Live` one never does. List open orders returns
`Pending` and `Live` orders. The app shows **Pending** in the Terminal's orders and counts it open.

Pages: `guides/orders` (states, diagram, table, response example, open orders, worked example), `concepts/hosts`,
`guides/streams` (`Opened`), `platform/terminal`.

### SubmitOrder answers as accepted

A submit returns once the host has accepted or refused the order: a refusal is an error, an acceptance the order as
accepted, usually `Pending`, or a later state the host already has. What happens after acceptance (a post-only the host
cancels, an IOC already finished) is on the order. Paper's submit waits only for admission, so a paper market order
can answer `Pending` before it fills; the quickstart no longer promises a filled response, and its read-back step shows
the filled order. A book lost just after paper accepted an order now ends it `Rejected` instead of failing the submit.

Pages: `guides/orders` ("What the response means"), `quickstart`, `paper/overview` ("When market data drops").

### 400 or 422 ValidationFailed

400 `InvalidRequest` is now only a body or cursor that cannot be read. A request that decoded but breaks a rule is
422 `ValidationFailed`, whichever check catches it: order rules, leverage off the grid, a position mode not offered,
a lowercase asset in an instrument, a non-canonical strike, a non-positive deposit, paper's `clientOrderId` format.
Valid input the host or state refuses stays 422 `Rejected` (paper's leverage or position mode change while not flat,
paper's admission refusals, an unknown fee tier). Messages now name their input and rule.

Pages: `api-reference/platform/errors` (codes table, "400 or 422"), `capabilities/overview` (section renamed
"NotSupported, ValidationFailed and Rejected"; no inbound links), `capabilities/order-rules`, `guides/orders`,
`concepts/instruments`, `paper/overview`.

### Paper ledger

Internal restructuring of the paper engine, plus bug fixes that make existing claims true (deposits racing fills,
torn margin reads, stranded holds, resting orders ending `Filled`, notional buys spending their notional). One claim
changed: a fill that is still settling no longer holds off liquidation; only a stale or unreadable price does.

Pages: `paper/leverage-and-liquidation`. `guides/streams` softened "every new posting arrives" to "new postings
arrive", since upstream now records that a transaction can miss the live stream; the history-first recovery already
covers it.

### Paper rejections and conflicts

A paper command refused after the earlier checks is 422 `Rejected` with its reason (was 500); a conflict that outlasts
retries is 503 `Unavailable`. Cancelling another account's order reads `404 OrderNotFound`. The errors page already
covers both codes. No change.

## Topics

### Implementation mode removed — update

`ImplementationMode` (`Native`/`Emulated`) is gone from `Supported` and `CursorQueryCapability` support values. The
public API no longer discloses emulation. Removed `implementation` from every JSON example; replaced the "Native and
emulated" section of `capabilities/overview` with "Partial results" (batch operations can partly succeed, read the
per-item results); removed the `implementation` row from the host-differences table and reworded the example reading
in `capabilities/host-capabilities`.

Pages: `capabilities/overview`, `capabilities/host-capabilities`, `capabilities/venue-capabilities`,
`paper/fees-and-funding`.

### Multiplexed account streams — update

Stream addresses drop the `{accountId}` path segment. One connection carries one stream type for up to 25 accounts,
subscribed and unsubscribed with `Subscribe`/`Unsubscribe` messages. Every server message has a `type`: `Subscribed`,
`Rejected` (per refused account, before `Subscribed`; account access and `NotSupported` are now reported here instead
of as HTTP errors before the upgrade), `Unsubscribed`, `Event` (with `topic`) and `Ended` (one account stopped,
connection stays open). New closes: `1008 "No topics"` after 30 s without a streaming account (from connect),
`1008` for undecodable client messages, `1011 "Stream failed"` (replaces `"Upstream stream ended"`), `1013 "Slow
consumer"`. Order holds per account, not across accounts.

From code (not spec text): accounts beyond the 25 limit are `Rejected` with `InvalidRequest`; a normally ended feed is
`Ended` with `UpstreamFailure` / "Upstream stream ended".

Rewrote `guides/streams` (protocol, limits, message table, `Ended`, keeping up, a queue-draining reconciliation sketch
over several accounts, close codes). Updated stream mentions in `authentication`, `api-reference/platform/overview`,
`conventions` and `errors`.

Tooling: `scripts/sync-platform-api.py` now writes one page per AsyncAPI channel (titled from the server `send`
operation), because each channel now also has a client `…Control` operation. Without this the stream pages were
overwritten with the Control operation and listed twice in navigation. Verified in `mint dev` that the channel page
renders both the control and server messages.

## Topics

### Single-instrument observations: update

GetPrices, GetBestQuotes, GetIndicativeFundings and GetOpenInterests (1–50 instruments, per-item `Observed` /
`Unavailable`) are gone. GetPrice, GetIndicativeFunding, GetOpenInterest and GetMarketStatistics read one instrument and
return the `{Type}Observed` value directly; an unsupported market is `422 NotSupported`. The Batch badge now covers
lists of identifiers only.

Pages: `concepts/venues` (batch reads section removed), `concepts/venues-and-hosts`, `capabilities/venue-capabilities`
("Unsupported markets" replaces the batch sections), `capabilities/overview`, `guides/market-data`,
`api-reference/platform/{conventions,overview}`.

### L1 and L2 order books: update

Best quote becomes the L1 book (GetOrderBookL1, SubscribeToOrderBookL1s; sizes always present; every stream message
is the complete top of book), the order book becomes L2 (GetOrderBookL2, SubscribeToOrderBookL2s). Capability keys
`orderBookL1`, `orderBookL2`; market descriptor `marketData.orderBookL1`.

Pages: as above plus `guides/streams`, `how-plurex-works`.

### Funding history: new content

ListFundingPeriods: finalised `{fundingTime, rate}` per perpetual, newest first, paged. Capability
`fundingPeriods.listFundingPeriods.byInstrument`, descriptor `marketData.fundingPeriods`.

Pages: `guides/market-data` and `concepts/venues` ("Funding history"), `capabilities/venue-capabilities`,
`capabilities/overview`, `api-reference/platform/{conventions,overview}`, `paper/fees-and-funding` (funding times).

### Support values split: update

`OperationSupport` and `CursorQueryCapability` are `Supported | NotSupported`; market-owned operations (market settings,
venue market data except L2 and trades) use `MarketSupport`: `PerMarket | NotSupported`.

Tooling: `sync-platform-api.py` classifies `MarketSupport` leaves and sets `perMarket` from them (the `resolves` flag in
`EXTRA` is gone); `EXTRA` rows renamed for the new operations, ListFundingPeriods added, account order stream rows
removed. `snippets/capability-check.mdx` shows either `PerMarket` or `Supported`, never both.

Pages: `capabilities/{overview,host-capabilities,venue-capabilities,order-rules}`, `guides/{streams,portfolio}`,
`paper/going-live`, `api-reference/platform/conventions`.

### Account order stream resets first: update

One `Reset` of the open orders once the host subscription is live, then an `Update` per change with the complete
order. Changes: Opened, Filled (no execution; use ListFills), Cancelled, Rejected, Other. Removed `Created`,
`FillApplied`, `Unknown`, `accountOrders.changes` and `includesFillDetails`. The transaction stream is unchanged.

Pages: `guides/streams` (account streams and local-copy procedures rewritten), `capabilities/host-capabilities`,
`guides/orders`, `paper/{overview,going-live}`, `api-reference/platform/{conventions,errors}`, `index`,
`how-plurex-works`.

### Errors and accounts: update

`Conflict` removed (account names need not be unique); `ProviderAccessDenied` added; `InvalidProviderCredentials`
narrowed; an unreadable account is `404 AccountNotFound`; unlisted instruments are `NotSupported`.

Pages: `api-reference/platform/errors`, `authentication`, `concepts/accounts`, `platform/add-exchange`, `quickstart`.

### Orders: update

SubmitOrder with a `clientOrderId` is `422 NotSupported` where the host does not accept one; 429 joins the unclear
outcomes; closed-order time bounds are approximate (dedupe by ID); a repeated cancel can return 404 or 409; trigger
reference rules under `HostSelected` and `UserSelectable`.

Pages: `guides/orders`, `capabilities/host-capabilities`, `api-reference/platform/errors`.

### Portfolio and transactions: update

`currentLeverageSetting` is null when a market has no leverage (paper reports null, not `Disabled`). Position sizes are
non-negative, empty sides are size "0". Transaction types defined: a maker rebate on a fill is a negative
`TradingFee`; `Rebate` is paid separately. `positionId`, `groupId` described. `settlementAsset` null for spot.

Pages: `guides/portfolio`, `concepts/{hosts,instruments}`, `capabilities/order-rules`, `paper/overview`.

### Paper: update

GetHostFeeTiers reads a paper host's tiers and default before an account exists. Funding times come only from the
venue's announced next funding time and finalised history. Funding postings carry the charged side in `positionId`.
Taken depth is held to the least the book has shown at the level since the take, with a time backstop. Paper's own
`clientOrderId` rules documented.

Pages: `paper/{overview,fees-and-funding,going-live}`, `platform/overview`.

### Spec feedback answered: no page changes

Four items were raised against `e0e6e385a` during this refresh and adopted in `030e972e1`:

1. `AccountTransactionType`: a maker rebate on a fill is a TradingFee with a positive amount.
2. `OrderChangeOpened`: at most once per order; orders in the Reset get no Opened, and an order first seen rejected gets
   only Rejected.
3. `AccountTransaction.positionId`: in hedging mode each side of a market has its own ID.
4. `CreateAccountCommand.feeTier` and `SetFeeTierCommand.tier`: an unknown ID is 422 Rejected. GetHostFeeTiers no
   longer lists 403 or 422.

The authored pages already said all of this (checked against source before raising). The code change in the commit is
a comment. Checked and not raised: removing `CandleSeriesSpec.maxHistoryAgeByInterval` was deliberate (`43cce7f25`).
